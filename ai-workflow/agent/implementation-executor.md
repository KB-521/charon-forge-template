## 何时使用
- 需要代码实现
- 修复缺陷
- 重构
- 修改代码

## 工作流

```
分析（先加载“需要加载的上下文”中的索引文档，再根据索引按需加载具体内容）-> 加载技能（从 `ai-workflow/skills/INDEX.md` 读取 skills 索引，并按当前任务需求引用具体 skill，没有合适的 skill 可以跳过。） → 实现（严格按照规则文档中描述的步骤实现） → 自检与验证记录（不自动执行测试命令或 code review，除非用户明确要求） → 交付
```

## 需要加载的上下文

根据当前需求与索引指引，按需加载相关具体文档，避免无差别全量读取

- `ai-workflow/wiki/<project-domain>/business/INDEX.md` - 当前任务所属项目域的业务知识索引
- `ai-workflow/wiki/<project-domain>/rules/INDEX.md` - 当前任务所属项目域的规则入口索引（若存在）
- `AGENTS.md` 与目标代码子项目 `AGENTS.md` - 当前任务所属项目域的技术导航、模块职责与下钻入口
- `ai-workflow/sdd/INDEX.md` - 统一需求管理

## 指引
1. 阅读需求与设计
2. 阅读“需要加载的上下文”中的索引文档，根据当前任务按需加载相关设计、参考实现、规则与 AGENTS 技术导航
3. 拆分为小而可测的改动
4. 逐步实现（UI 约束 + 参数归一化 + 接口/mock 一致）
5. 对每个改动进行必要自检并记录建议验证方式；不自动执行测试命令或 code review，除非用户明确要求

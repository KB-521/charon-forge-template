# PRD 审查清单

## 1. 结构化完整性
| 检查项 | 通过标准 |
|---|---|
| 背景与目标 | 说明业务背景、目标、成功标准 |
| 范围与非范围 | 明确本期做什么、不做什么 |
| 角色与权限 | 角色定义清晰，权限边界明确 |
| 功能点目录 | 功能点可枚举，命名一致 |
| 风险与待确认 | 有集中管理区并可追踪 |

## 2. 功能点清晰度
| 检查项 | 通过标准 |
|---|---|
| 需求描述 | 描述用户动作和系统行为 |
| 业务规则 | 输入约束、规则、计算口径明确 |
| 异常边界 | 失败、冲突、空状态、越权有定义 |
| 状态流转 | 状态名唯一，流转条件明确 |
| 权限限制 | 每个关键操作有角色限制 |

## 3. 可实现性与可测试性
| 检查项 | 通过标准 |
|---|---|
| 可实现 | 不依赖未知前提，依赖项可识别 |
| 可测试 | 验收标准可转测试用例 |
| 数据口径 | 指标定义唯一且可计算 |
| 接口需求 | 关键读写操作可映射到 API |
| 兼容与迁移 | 变更影响与迁移策略可识别 |

## 4. 一致性与可维护性
| 检查项 | 通过标准 |
|---|---|
| 术语一致 | 同一概念仅一个名称 |
| 文案一致 | 状态、按钮、动作命名一致 |
| 跨章节一致 | 前后规则不冲突 |
| 版本一致 | 变更记录与正文一致 |

## 5. 非功能与治理
| 检查项 | 通过标准 |
|---|---|
| 安全与合规 | 隐私、权限、审计要求明确 |
| 性能要求 | 核心性能目标有口径 |
| 可观测性 | 日志、监控、告警有要求或预留 |
| 上线策略 | 灰度/回滚/开关策略明确或待确认 |

## 6. 业务一致性对照（必查）
| 检查项 | 通过标准 |
|---|---|
| 业务基线文档下钻 | 已读取至少 1 篇 `wiki/<project-domain>/business` 具体文档与 1 份同域历史 SDD 文档（若存在） |
| 功能点对照矩阵 | 每个核心功能点均有“对照文档 + 一致/冲突/缺失结论” |
| 旧逻辑兼容性 | 明确“沿用旧逻辑 / 变更旧逻辑 / 废弃旧逻辑”的处理方式 |
| 规则冲突处理 | 与 `wiki/<project-domain>/rules` 冲突时有明确结论与待确认项 |
| 缺失基线风险 | 无可用基线时已显式记录风险与补齐动作 |

## 严重级别判定
| 级别 | 判定标准 |
|---|---|
| BLOCKER | 不修复无法开始设计或开发 |
| MAJOR | 容易导致实现偏差或返工 |
| MINOR | 不影响主线但会降低质量 |
| SUGGESTION | 可选优化，不阻断推进 |

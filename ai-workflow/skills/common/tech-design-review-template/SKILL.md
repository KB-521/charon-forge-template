# 技术方案 Review 模版生成

为指定技术方案生成可执行的 Review 模版，统一问题记录格式与解决方案。

## 何时使用

- 技术方案已生成，准备组织评审。
- 需要先建 Review 文档，再按 Review 结论修订技术方案。
- 需要保证“问题 -> 解决方案”可追溯。

## 输入要求

1. 目标技术方案内容（必填）：至少提供方案标题、评审范围、关键章节摘要、核心接口或数据模型信息。
2. 关联 PRD 内容（建议提供）：至少提供需求摘要、功能点、约束和验收标准。
3. 可选：历史 Review 内容（若存在旧版，需要做增量复用）。

## 需要加载的上下文

- 目标技术方案文档。
- 关联 PRD（如有）。
- `references/template.md`。
- 若存在历史 Review 文档，仅用于复用已确认字段，不得直接继承结论。

## 强制流程

1. 采集事实
- 读取技术方案，提取基础元信息：项目名、方案类型、评审范围、关键章节。
- 至少抽取以下对象：核心链路、API/接口清单、数据模型/表、外部依赖边界。
- 若同名 Review 已存在，先读取并识别可复用内容（如版本号、评审人、修订记录）。

2. 计算目标产物
- 目标文件固定放在当前变更包的设计评审目录。
- 命名规则：`<技术方案文件名去后缀>-review.md`。
- 示例：技术方案文件名为 `<project>-backend-design.md` 时，Review 文件名为 `<project>-backend-design-review.md`。

3. 生成 Review 模版
- 以 `references/template.md` 为骨架写入目标文件。
- 预填以下字段：`关联技术方案`、`关联 PRD`、`评审范围`。
- 对“评审范围”至少写入从技术方案中抽取的关键章节，禁止空内容输出。

4. 处理增量场景
- 若目标文件已存在：合并保留已补充内容（如 `解决方案`、`状态`、`备注`）。
- 新增或改动章节需重建对应问题模板，避免旧结论失效。
- 对无法确认的项统一标注 `待确认`，不得补写为既定事实。

5. 自检
- 核验模板中的每个“评审范围项”都能回溯到技术方案章节。
- 核验问题清单字段齐全：`问题/解决方案`。
- 核验输出仅新增/更新 Review 文档，不改写技术方案原文。

## 门禁（Gate）

- Gate 1：缺少目标技术方案文档，禁止生成。
- Gate 2：评审范围无法追溯到技术方案章节，禁止交付。
- Gate 3：将“待确认项”写成既定事实，视为失败。
- Gate 4：直接改写技术方案正文而非写入 Review 文档，视为失败。

## 输出产物

1. Review 模版文档：
- 当前变更包设计评审目录中的 `<技术方案文件名>-review.md`
2. 生成结果摘要（用于回复用户）：
- 目标文件路径
- 自动预填项清单
- 需人工补充项清单

```markdown
|---|---|---|

- [x] 问题清单字段齐全

```

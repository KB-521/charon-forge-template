# 后端拆分规则索引

后端拆分采用“复杂度预算 -> 任务类型 -> 依赖边界 -> JIT 细化”的方式生成父计划和子任务。先读取 `../common/INDEX.md`，再按下表命中后端规则。

| 任务事实 | 读取文件 |
| --- | --- |
| 需要判断复杂度、拆分预算、任务类型、停止/必须拆分条件 | `granularity.md` |
| 需要判断前置依赖、阻塞、并行、写入边界 | `dependency.md` |
| 需要生成父计划和子任务骨架 | `templates.md` |
| 需要最终 DoD、门禁和自检 | `gates.md` |

## 默认执行顺序

1. 读取输入设计：PRD、后端设计、API 契约、逻辑/物理模型、发布约束。
2. 读取 `granularity.md`，给出 Score、Level、Split Budget、Task Type。
3. 读取 `dependency.md`，生成依赖图、并行队列和改动边界。
4. 读取 `templates.md` 落地父计划、父需求 `INDEX.md` 和子任务。
5. 读取 `gates.md` 做结束前自检。

## 关键原则

- 子任务数量由复杂度和独立验收出口决定，不使用固定“至少 N 个”的规则。
- 最近可执行的 1~3 个任务写完整执行细节；依赖尚未稳定的后续任务只写 Outline，待前置契约明确后再细化。
- 任务拆分服务于可实现、可验证、可并行，不为了拆分而拆分。

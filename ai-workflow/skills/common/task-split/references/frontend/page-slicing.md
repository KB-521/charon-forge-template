# 前端页面拆分

## 输入

- 前端技术方案：优先读取 `design/<design-package>/*-frontend-solution.md`。
- PRD：用于补齐功能点来源，不作为唯一输入。
- 原型/交互稿：用于确认页面、路由和状态。
- API 契约：用于接口映射，不作为页面拆分主维度。

## 页面拆分规则

- 必须按页面维度拆分，禁止按接口维度或技术层维度直接拆分。
- 每个子任务必须且只能覆盖 1 个页面 + 1 条主路由。
- 即使“列表 + 详情”高度耦合，也必须拆成两个子任务，通过依赖连接。
- 公共能力只能作为页面任务内部步骤，不得单独占用子任务编号。
- 若单页面复杂度过高，允许拆成同一页面多个子任务，例如 `P-03-A`、`P-03-B`。

## 页面任务内容

每个页面任务必须覆盖：

- 页面目标。
- 触发动作。
- 校验规则。
- 成功路径。
- 失败路径。
- 回退策略。
- `loading`、`empty`、`error`、`no-permission` 状态。
- 页面级、组件级、动作级权限。
- 接口路径、方法、用途、触发时机、成功/失败处理。

## 粒度

- 单个页面任务建议最多 3~6 个接口，或 1 条主交互链路 + 必要查询接口。
- 命中任意两项时，继续拆成同一页面内的多个子任务：复杂表单、多角色权限分歧、批量操作和部分失败、大文件上传/下载、复杂预览、复杂状态机。

# 前端拆分规则索引

前端拆分采用页面优先策略。先读取 `../common/INDEX.md`，再按下表命中前端规则。

| 任务事实 | 读取文件 |
| --- | --- |
| 需要按页面拆分、判断页面粒度、生成 PageKey | `page-slicing.md` |
| 需要判断页面依赖、并行队列和改动边界 | `dependency-and-parallel.md` |
| 需要生成父计划和页面子任务骨架 | `templates.md` |
| 需要最终门禁和自检 | `gates.md` |

## 默认执行顺序

1. 读取前端技术方案、PRD、原型/交互稿、API 契约。
2. 读取 `page-slicing.md` 生成页面清单、PageKey 和一页一任务映射。
3. 读取 `dependency-and-parallel.md` 生成依赖和并行队列。
4. 读取 `templates.md` 落地父计划、父需求 `INDEX.md` 和页面子任务。
5. 读取 `gates.md` 做结束前自检。

## 核心原则

- 一个子任务只能绑定 1 个页面和 1 条主路由。
- 公共组件、hooks、请求封装只能挂靠到消费页面任务，默认不独立占用子任务编号。
- 单页面过复杂时可以拆成同一页面的多个子任务，但不能跨页面混拆。

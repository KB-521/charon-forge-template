# 01-架构与模块

## 适用场景

新增模块、调整依赖、引入技术栈、生成包结构、拆分能力边界、初始化项目骨架时读取本规则。

## 命中条件

| 维度 | 命中信号 |
| --- | --- |
| 产物 | 模块、包结构、依赖、构建文件、生成器、客户端、配置入口 |
| 动作 | 新建模块、调整依赖、引入技术栈、拆分职责、初始化骨架 |
| 风险 | 依赖方向、跨层调用、技术栈漂移、重复封装、启动模块堆业务 |
| 可跳过 | 只改已有方法内部逻辑且不改变模块、依赖或包结构 |

## 01.1 技术栈选型

| 场景 | 规则 |
| --- | --- |
| 新增框架 | 优先复用仓库既有技术栈，确需新增时先写选型说明 |
| 新增中间件 | 说明用途、替代方案、运维成本、失败影响 |
| 新增外部客户端 | 优先复用已有封装，禁止在业务类里临时 new 客户端 |
| 新增持久化方案 | 先确认现有数据库、缓存、对象存储是否满足 |

## 01.2 版本管理

| 对象 | 规则 |
| --- | --- |
| Maven 依赖 | 版本集中在父 POM、BOM 或统一版本矩阵 |
| 插件 | 构建插件集中管理，禁止模块私自漂移 |
| 生成器 | 生成器版本和配置统一维护 |
| 传递依赖 | 新增依赖前检查冲突、重复和安全风险 |

## 01.3 模块职责

| 层级 | 职责 |
| --- | --- |
| commons | 通用工具、基础异常、公共常量、通用配置 |
| domain | PO、DTO、VO、BO、Query、Enum、ErrorCode |
| dal | DAO、Mapper、SQL、数据访问对象 |
| biz | Service、业务编排、事务、外部协同 |
| bootstrap | 启动、装配、配置、入口暴露 |

## 01.4 依赖方向

| 规则 | 说明 |
| --- | --- |
| 单向流动 | 上层依赖下层，下层不得反向依赖上层业务或启动模块 |
| 抽象下沉 | 下层需要上层能力时，优先抽象接口下沉 |
| 边界隔离 | 跨模块共享模型必须明确归属，禁止复制同义类 |
| 启动隔离 | bootstrap 不承载业务流程 |

## 01.5 包结构

| 包类型 | 内容 |
| --- | --- |
| model | PO、DTO、VO、BO、Query 分目录维护 |
| api | Controller、Endpoint 或项目等价公开入口 |
| service | Service 接口和实现 |
| dao | DAO、Mapper、PlusDAO 等数据访问 |
| adapter | 外部调用、协议转换、媒体 URL 适配 |
| constants/enums | 常量、枚举、错误码、锁 key |
| config | Spring Bean、配置属性、开关装配 |

## 代码生成检查清单

- 新文件是否落在正确模块和包路径。
- 新依赖是否已有同类能力可复用。
- 下层模块是否引入了上层业务依赖。
- 启动模块是否只保留装配职责。
- 模型、API、Service、DAO、Adapter、Config 是否分目录维护。

## 高风险反例

- 为一个接口临时新增基础设施依赖。
- 在启动模块或 Controller 中堆业务流程。
- DAO 模块反向依赖 biz/service。
- 同一类对象散落在多个不一致包路径。

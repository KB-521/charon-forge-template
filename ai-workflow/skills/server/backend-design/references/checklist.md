# 后端技术方案检查清单

## 1. 输入冻结

- [ ] 已引用 PRD、任务、评审结论或用户补充约束。
- [ ] 已完成“功能点 -> 动作 -> API”抽取。
- [ ] 待确认项有 owner、截止时间和当前状态。
- [ ] 核心口径未确认时，文档状态保持“评审版”。

## 2. API 契约

- [ ] API 清单覆盖 PRD、tasks 和用户显式指定接口。
- [ ] 每个接口包含来源、变更类型、兼容影响、API、Method、用途、详细说明、request、response、主链路。
- [ ] `request` 与 `response` 字段展开到 `type/comment/default`。
- [ ] 已完成 `PRD -> API`、`Tasks/用户指定 -> API`、`API -> PRD/Tasks` 三向追溯。

## 3. 数据模型引用

- [ ] 涉及数据模型、表结构、字典、枚举或兼容 SQL 时，已引用 `server/data-model-design` 产物或结论。
- [ ] 数据模型结论与 API、状态机、事务边界一致。
- [ ] 不涉及数据变更时，已明确“不涉及”及依据。

## 4. 实现边界

- [ ] 模块边界符合 `server/AGENTS.md` 和现有代码结构。
- [ ] 已给出实现层映射矩阵，能从功能点追溯到数据模型、持久化、业务、入口、测试和 YApi。
- [ ] 鉴权、权限、上下文、幂等和错误码口径明确。
- [ ] 事务边界、外部依赖、超时、重试、降级和补偿策略明确。
- [ ] 涉及外部能力时，已记录真实接入点、来源证据和确认状态；找不到时已标注 BLOCKER。
- [ ] 状态机、异步任务或消息链路的异常回退路径明确。

## 5. 评审判定

- [ ] 无未处理 BLOCKER。
- [ ] 每个功能点可映射到模块、API、数据影响和业务流程。
- [ ] 命中规则和自检结论已记录。
- [ ] 若存在覆盖缺口或核心待确认项，文档明确标注为“评审版”。

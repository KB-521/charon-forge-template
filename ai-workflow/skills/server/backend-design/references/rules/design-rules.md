# Backend Design Rules

## 适用场景

后端编码前需要冻结 API、模块边界、数据影响、外部依赖、状态机、权限、幂等、事务或兼容口径时读取。

## 命中条件

| 维度 | 命中信号 |
| --- | --- |
| 产物 | 后端技术方案、API 契约、实现层映射、数据模型引用 |
| 动作 | 新增接口、修改链路、冻结方案、确认外部能力、评审设计 |
| 风险 | 需求追溯缺失、字段契约漂移、外部能力猜测、兼容口径不明 |
| 可跳过 | 不涉及后端方案冻结 |

## 决策表

| 场景 | 规则 |
| --- | --- |
| 动作抽取 | 先从 PRD/任务抽取“功能点 -> 动作 -> API”基线，再写接口清单 |
| API 契约 | 覆盖主文档 API 清单、tasks 明确接口和用户显式指定接口 |
| 字段级契约 | request/response 展开到 `type/comment/default`，禁止只写 DTO/ref |
| 数据影响 | 涉及表、字段、索引、字典、枚举或兼容 SQL 时，引用 `server/data-model-design` 产物 |
| 实现映射 | 复杂需求必须给出功能点到数据、持久化、业务、入口、测试、YApi 的映射 |
| 外部能力 | 用户、租户、组织、权限、账户、余额、扣费、退款、审计、通知等能力必须从真实来源确认 |

## 门禁

- 必须完成 PRD/API/Tasks 三向追溯。
- 未处理 BLOCKER、核心待确认项未确认、追溯不完整或外部能力未确认时，只能输出评审版。
- 新增设计索引 ID 使用 `DES-BE-<YYYYMMDDHHmmss>-<change-or-package>`，不使用纯当日递增序号抢占唯一性。
- 敏感信息、账号、连接串、token、签名和密钥不得写入设计文档、日志或示例。
- SDK、Client、Facade、Adapter、YApi、配置项、码值和表结构必须来自源码、契约或已确认输入。
- 只设计当前需求需要的最小闭环；涉及旧接口、旧数据或资金资产链路时必须说明兼容、回滚和剩余风险。

## 交付要求

| 项 | 必填内容 |
| --- | --- |
| 输入来源 | PRD、任务、评审结论、现有实现证据 |
| API 契约 | API 清单、字段级 request/response、错误码和兼容影响 |
| 数据影响 | data-model-design 产物引用或不涉及依据 |
| 实现映射 | 各功能点对应的持久化、业务、入口、测试和 YApi |
| 评审状态 | 定稿版/评审版、BLOCKER 和待确认项 |
| 交付证据 | 命中规则、输入来源、验证或未验证原因、剩余风险 |

## 高风险反例

- 跳过动作抽取直接列 API。
- 外部能力未确认就写死 SDK、方法名或字段。
- 数据模型未冻结就定稿依赖该模型的状态机或兼容策略。

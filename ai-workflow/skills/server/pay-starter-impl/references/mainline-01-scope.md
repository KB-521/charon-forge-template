# 1. 冻结输入和目标边界

## 何时读取

开始端到端新增支付渠道、方案设计或范围评审时读取本文件。

## 执行动作

- 确认渠道名称、支付形态、承接运行模块、是否需要一次性支付、订阅、主动退款、渠道退款事实、提现或 payout。
- 读取 [rules/INDEX.md](./rules/INDEX.md)，再按命中条件读取 starter 或 measure 规则中的“源码入口”。
- 用 `rg` 定位当前仓库里最相关的已有实现，不凭记忆判断。

## 产出

- 渠道能力清单。
- 涉及仓库和目标模块。
- 明确不做的能力。
- 需要用户补充的信息。

## 门禁

能力不清时不得开始建模块；尤其不要默认把订阅、退款、提现混进一次性支付链路。

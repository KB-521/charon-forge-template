# Unit 测试代码场景矩阵

本文件用于生成 Java 单元测试代码，不生成规格文件和 JSON suite。

## 覆盖档位

- `full`：默认按“正例 / 反例 / 边界 / 并发”四大类组织测试方法。
- `minimal`：至少覆盖 1 个成功场景 + 1 个失败或边界场景。
- `minimal` 命中并发、状态机、锁、补偿、导入导出、open 等高风险主题时，仍需补专项测试。

## 正例

| scene | 何时必填 | 说明 |
| --- | --- | --- |
| `success_basic` | 必填 | 合法输入返回预期结果 |
| `success_with_optional_branch` | 有可选分支时 | 命中可选条件、分支逻辑、默认值逻辑仍正确 |

## 反例

| scene | 何时必填 | 说明 |
| --- | --- | --- |
| `illegal_argument` | 必填 | 非法参数、缺参、无效枚举、格式错误 |
| `business_exception` | 必填 | 业务异常、断言失败、状态不允许 |
| `dependency_failure` | 有依赖时 | mock 依赖抛错、返回异常值、超时或空结果 |
| `regression` | 修缺陷或改逻辑时 | 历史缺陷先失败后通过 |

## 边界

| scene | 何时必填 | 说明 |
| --- | --- | --- |
| `null_or_empty` | 必填 | null、空字符串、空集合、空对象 |
| `min_max_limit` | 有边界值时 | 最小值、最大值、超界值、临界长度 |
| `critical_state` | 状态流转类 | 前置状态、终态、状态切换边界 |
| `idempotent` | 幂等逻辑时 | 重复调用、副作用只执行一次、重复写保护 |

## 并发

| scene | 何时必填 | 说明 |
| --- | --- | --- |
| `concurrent_invocation` | 方法包含锁、共享状态、幂等控制或副作用去重时必填 | 多线程并发调用同一方法或同一业务键，验证返回与副作用收口一致 |
| `multi_instance_concurrency` | 依赖 Redis/DB 唯一约束、分布式锁、幂等表等跨实例协调时必填 | 通过共享依赖 mock 或可控桩模拟多实例竞争，验证最终只有一次有效提交或状态推进 |

说明：

1. `multi_instance_concurrency` 可通过两个 service 实例共享同一锁或仓储 mock 并发调用来模拟，不要求真实起多个进程。
2. 纯函数、无共享状态且无外部副作用的方法，可把并发场景标为 `not_applicable`，但必须说明原因。

## 实现分支清单

生成测试方法前，必须先枚举实现分支。最少检查以下分支类型：

| branchType | 何时必填 | 说明 |
| --- | --- | --- |
| `entry_guard` | 必填 | 参数校验、状态前置校验、上下文前置检查 |
| `success_path` | 必填 | 主成功路径 |
| `optional_noop` | 有默认值、可跳过步骤、提前返回时 | 例如可选参数缺失直接跳过某个依赖调用 |
| `local_consistency_guard` | 有本地状态、缓存、仓储结果校验时 | 例如重复记录、更新条数异常、状态快照缺失 |
| `dependency_call` | 有 mock 依赖、仓储、远端客户端、消息、缓存时 | 每个依赖点至少枚举成功与可达失败形态 |
| `post_side_effect` | 有后置写入、事件、异步、补偿动作时 | 覆盖前序成功、后序失败的分支 |
| `concurrency_control` | 有锁、共享状态、幂等控制时 | 覆盖竞争失败、锁中断、多实例共享依赖竞争 |

补充要求：

1. `dependency_call` 按调用点拆分，不得用“一条依赖失败”概括所有外部依赖。
2. 存在共享锁或可中断等待时，必须把“竞争失败”和“中断 / 异常”分支分开列。
3. 存在短路返回或 no-op 分支时，必须显式建项，不得只在交付说明里提一句。

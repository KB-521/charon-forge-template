# 后端实现提示词

## 作用

把用户输入整理成可执行的后端实现指令。本文只提供通用提示词，不包含项目名、包名、依赖、外部系统 client、端口或敏感配置。

## Prompt

```text
请在目标项目中实现后端业务执行层，先读取项目说明、规则索引、业务契约和相似源码，再按最小闭环修改 Service/Facade/Job/Consumer/EventHandler 等业务组件。

【需求背景】
- change-id：
- 业务目标：
- 不做项：

【业务契约】
- Service/Facade/worker 名称：
- 业务动作：
- 输入字段：
- 输出字段：
- 错误语义：
- 鉴权/权限边界：

【实现落点】
- Service 层：
- Worker 层（定时/MQ/事件，如有）：
- 持久化方法契约表：
- Worker/MQ/Event 契约（触发源/消息/幂等键/锁/重试/ack-nack/补偿/调用 Service）：
- 外部能力：
- 枚举/配置：
- 需要复用的相似实现：

【规则与边界】
- 参数校验：
- 事务边界：
- 异常处理：
- 日志与脱敏：
- 幂等/锁/并发：
- 数据、枚举、兼容影响：
- HTTP 入口影响（如有，转 entry-impl）：

【验证】
- 建议执行命令：
- 必须覆盖的成功路径：
- 必须覆盖的失败/边界路径：

现在开始实现；不要只给建议。若缺少关键输入，先列出缺口和风险，不要猜项目路径、包名、注解或外部依赖。
```

## 使用规则

- 老项目必须以目标项目相似源码为准。
- 新项目必须先确认分层、命名、响应封装、持久化和测试约定。
- 不复写密钥、账号、连接串、token 或外部系统凭据。
- 若实现发现需要 SQL/schema/兼容数据、Java 持久化骨架、HTTP 入口或数据模型设计，停止并分别切换到 `persistence-impl`、`skeleton-codegen`、`entry-impl` 或 `data-model-design`。

# Logging Comment

## 适用场景

新增或修改 Service 主链路、关键分支、状态变化、外部调用、异常处理、定时任务、异步任务、注释或 TODO 时读取。

## 命中条件

| 维度 | 命中信号 |
| --- | --- |
| 产物 | 日志、业务注释、TODO/FIXME、交付说明 |
| 动作 | 新增主链路、增加分支、外部调用、状态变化、异常捕获 |
| 风险 | 敏感信息泄露、失败上下文缺失、重复日志、业务口径不清 |
| 可跳过 | 纯机械改动且无业务语义 |

## 日志级别

| 级别 | 应该打印 | 不应该打印 |
| --- | --- | --- |
| `debug` | 入参摘要、查询条件、命中分支、调试定位信息 | 完整 DTO、敏感字段、高频大对象 |
| `info` | 低频业务关键事件：状态变化、任务开始/结束摘要、外部副作用触发、重要业务结果 | 高频循环、每条列表/明细、纯查询成功 |
| `warn` | 可恢复但非预期：降级、重试、跳过脏数据、幂等重复、外部超时但已兜底 | 真实失败、不可恢复异常 |
| `error` | 每个 catch 中打印一条最终失败日志，包含异常信息、异常栈和关键上下文 | 同一 catch 连续多条 error、无异常栈、无上下文 |

## 场景规则

| 场景 | 日志/注释要求 |
| --- | --- |
| Service 入口 | `debug` 记录业务主键、用户、租户、动作摘要 |
| 关键分支 | 低频关键分支用 `info` 记录分支原因、业务主键和处理结果；高频分支用 `debug` 或不打印 |
| 状态变化 | `info` 记录变更前后状态和触发动作 |
| 外部调用 | 发起/完成的低频副作用用 `info`；请求摘要、查询条件和命中分支用 `debug` |
| 定时/MQ/批处理 | `info` 记录开始/结束摘要、处理数量、成功失败统计；循环内明细不逐条 info |
| 可恢复异常 | `warn` 记录降级、重试、跳过、幂等重复和下次可恢复条件 |
| 异常处理 | 每个 catch 中保留一条 `error`，必须带异常信息、异常栈和关键上下文 |
| 复杂业务 | 注释解释业务口径、兼容边界和复杂分支，不做逐行翻译 |

## 门禁

- 日志不得复写 token、密码、连接串、完整手机号、证件号、完整请求体等敏感信息。
- `info` 只打印低频业务关键事实；禁止在高频循环、列表明细、纯查询成功路径中刷屏。
- `warn` 只用于可恢复但非预期的问题；不可恢复失败必须进入 `error`。
- 每个 catch 必须打印一条 `error`，包含异常信息、异常栈、业务主键、租户/组织/用户上下文和 action；同一 catch 禁止连续多条 error。
- TODO 不能替代测试、幂等、安全、异常处理或发布动作。
- 注释只解释业务口径和复杂边界，不翻译简单语法。

## 交付要求

| 项 | 必填内容 |
| --- | --- |
| 日志证据 | 新增或复用的 debug/info/warn/error 关键日志点 |
| error 上下文 | catch 中 error 是否包含异常信息、异常栈、业务主键和关键上下文 |
| 注释说明 | 核心复杂逻辑是否已说明 |
| TODO/FIXME | 动作、触发条件、收敛方向和风险 |

## 高风险反例

- catch 中连续打印多条 error。
- catch 中没有打印 error，或只打印 `e.getMessage()` 不带异常栈。
- 直接打印完整 DTO 或第三方响应。
- 高频循环内逐条打印 info。
- 用 warn 掩盖不可恢复失败。
- `TODO: 后续处理` 这类无法追踪的欠账。

# Transaction Consistency

## 适用场景

生成或修改多表写、同一业务动作内多次写、状态流转、事务注解、跨系统协同、补偿、计费或资产一致性链路时读取。

## 命中条件

| 维度 | 命中信号 |
| --- | --- |
| 产物 | Service 写方法、事务注解、状态更新、补偿记录、计费处理 |
| 动作 | 新增写链路、修改状态、调用外部系统、发送消息、失败回滚 |
| 风险 | 长事务、远程副作用悬挂、重复写、状态竞争、补偿不可重放 |
| 可跳过 | 纯只读且无副作用 |

## 决策表

| 场景 | 事务策略 | 必须说明 |
| --- | --- | --- |
| 单表单次写入 | 默认不加显式事务 | 依赖数据库单语句原子性；说明无跨表/多次写/外部副作用 |
| 单表多次写入 | 视为事务候选 | 多次写之间是否必须同成功同失败 |
| 单库多表强一致 | 本地事务 | 回滚异常类型和状态更新条件 |
| 状态机写入 | 条件更新或锁 | 前置状态、非法流转错误码、并发保护 |
| 先远程后本地 | 分段事务/补偿 | 本地失败后的回退或补偿 |
| 先本地后远程 | 失败状态/重试 | 远程失败后的状态和重试 |
| 消息或异步副作用 | 最终一致 | 幂等键、重试、补偿和可观测证据 |

## 门禁

- 单表单次写入默认不加显式事务；除非存在状态一致性、幂等记录、补偿、资产/计费或必须同失败的副作用。
- 涉及多表写、同一业务动作内多次写、资产、计费、状态流转和补偿时，必须明确事务边界、失败语义、幂等和回滚策略。
- 默认避免在事务内包裹长耗时外部调用；确需使用必须说明原因和超时控制。
- 补偿动作必须幂等、可重复执行、可追踪。

## 交付要求

| 项 | 必填内容 |
| --- | --- |
| 是否需要事务 | 单表单次写默认不加；多表或多次写需说明事务边界 |
| 事务边界 | 哪些写操作在同一事务内，哪些在事务外 |
| 失败语义 | 每类失败返回、记录或状态变化 |
| 幂等策略 | 幂等键、唯一约束或条件更新 |
| 补偿策略 | 重试、补偿记录、人工兜底或不需要的依据 |

## 高风险反例

- 一个事务包住长时间第三方调用。
- 单表单次写入为了“保险”随手加事务。
- 多表写或多次写没有事务边界说明。
- 远程调用成功后本地失败没有补偿。
- 状态更新只按 ID 改，不校验当前状态。

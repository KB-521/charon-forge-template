# Code Review Rules

## 适用场景

用户明确要求后端 code review、PR 评审、提交前复核或问题定位时读取。

## 命中条件

| 维度 | 命中信号 |
| --- | --- |
| 产物 | review 结论、PR 评审、缺陷定位、提交前复核 |
| 动作 | 审阅 diff、排查问题、复核修复、评估测试缺口 |
| 风险 | 安全、数据、事务、SQL、接口契约、兼容、测试不足 |
| 可跳过 | 不涉及后端评审 |

## 评审顺序

| 顺序 | 重点 |
| --- | --- |
| 1 | 安全配置、敏感信息、越权和数据风险 |
| 2 | 功能正确性、边界、状态、幂等和并发 |
| 3 | 事务一致性、外部调用、补偿和回滚 |
| 4 | DAO、MyBatis、SQL 注入、分页排序和索引 |
| 5 | API 契约、DTO/VO、YApi 或客户端字段一致性 |
| 6 | 日志、注释、文档和测试资产 |

## 门禁

- Findings 优先，按严重级别排序；每条问题包含文件行号、风险、影响范围和最小修复建议。
- 只评论可验证事实；信息不足时标注待确认，不用风格偏好替代缺陷。
- 新增或修改真实凭据、token、AK/SK、数据库连接串、网关密钥等按阻塞风险处理；历史未触碰配置标为历史风险。
- 高风险分支、边界、并发、幂等、回调、计费、导入导出缺测试时列为风险。
- SDK、Client、Facade、Adapter、YApi、配置项、码值和表结构必须基于当前源码或已确认契约，不凭记忆下结论。
- 只评审当前 diff 和直接影响面；涉及旧接口、旧数据、租户隔离或资金资产链路时必须单独说明兼容风险。

## 交付要求

| 项 | 必填内容 |
| --- | --- |
| Findings | 严重级别、文件行号、风险、影响和修复建议 |
| Open Questions | 信息不足或需要用户确认的事项 |
| Test Gaps | 未覆盖的关键分支和建议验证 |
| Summary | 只在 findings 后简要说明 |
| Evidence | 命中规则、源码或 diff 证据、未验证原因 |

## 高风险反例

- 用风格偏好替代可验证缺陷。
- 对历史未触碰配置直接标成本次阻塞。
- 只总结优缺点，不列具体文件和风险。

# 后端代码评审检查清单

## 安全

- 敏感配置评审必须先区分 profile、是否本次 diff 新增或修改、是否历史基线；禁止把本次未触碰的历史 `local/dev` 配置直接作为当前变更 P0。
- `pre/prod` 明文真实凭据、token、AK/SK、数据库连接串、网关密钥等：若本次新增或修改，按 P0 阻塞；若历史已有但本次未改，列为历史风险或待治理，不作为当前变更阻塞。
- `local/dev` 明文真实配置：若本次新增或修改，按团队配置约定标记为 P1/P2 并要求确认替代方式；若历史已有且本次未改，不作为本次 finding。
- `${ENV}`、`${xxx}` 占位符、Jasypt 密文、密钥系统引用、`mock` / `dummy` / 明确不可用示例值不按凭据泄露处理。
- 输出证据只写文件、行号和配置 key，不复写真实敏感值。
- 配置必须优先走环境变量、Jasypt 密文或密钥系统；确需保留 `local/dev` 本地开发配置时，必须能从项目规则或团队约定中确认。
- 严查 SQL 注入风险，禁止字符串拼接 SQL。
- 接口必须校验鉴权与权限边界。

## 正确性

- Entry、Service/Facade、Persistence 之间的调用方向清晰；Worker/MQ/Event 入口只触发并调用业务服务。
- 未把业务逻辑堆进 Endpoint / Controller / Mapper / Job / Consumer。
- 业务分支覆盖正常、异常、边界与幂等场景。
- 空值、默认值、状态流转符合需求。
- 时间、金额、精度处理可靠。

## 事务与一致性

- 多表写操作有正确事务边界。
- 回滚策略覆盖受检/非受检异常。
- 不存在脏读、重复写、覆盖写、并发竞争问题。

## DAO / SQL

- 不存在明显 N+1 查询。
- 索引命中、where 条件、排序字段合理。
- 分页稳定且有明确排序。
- Mapper 参数和映射关系匹配。

## 日志与观测

- 对照 `references/rules/review-rules.md`。
- 入口日志、异常前错误日志、catch 中单条 `log.error(...)` 约束成立。
- 日志包含必要上下文，但不泄露敏感信息。
- 长耗时调用有超时/重试控制；关键链路具备可观测指标或明确缺口。

## 注释与文档

- 对照 `references/rules/review-rules.md`。
- 核心方法注释覆盖用途、入参、出参、副作用/异常语义。
- 核心服务主链路有中文分段注释，且能还原执行顺序。
- 命中 Endpoint、路由、DTO/VO 或分页结构时，核对 `*-api-contract.md` 与源码一致。
- 模块入口、职责或下钻方式变化时，检查 `server/AGENTS.md` 的“模块职责与常见下钻”是否同步。

## 测试资产

- 新逻辑是否补了对应测试，或说明未补原因。
- 缺陷修复是否有可复现回归用例。
- 断言是否覆盖关键业务字段，而非只断状态码。
- 命中可测试后端代码时，检查现有测试资产、`server/test-codegen` 生成结果或用户明确跳过原因。
- 若已有测试资产，检查“测试代码 -> 校验/执行结果 -> 风险说明”链路完整。

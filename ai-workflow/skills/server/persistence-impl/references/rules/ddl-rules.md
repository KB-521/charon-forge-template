# DDL Rules

## 适用场景

新增或修改表、字段、索引、唯一约束、默认值、注释、字符集、存储引擎时读取。

## 命中条件

| 维度 | 命中信号 |
| --- | --- |
| 产物 | DDL、schema delta、rollback/fixforward |
| 动作 | 新建表、改字段、增索引、改唯一约束、改默认值、补注释 |
| 风险 | 锁表、存量数据不兼容、唯一键冲突、索引失效、老代码不兼容 |
| 可跳过 | 不涉及 DDL |

## 门禁

- DDL 必须来自冻结的数据模型或已确认源码事实。
- 无参考 SQL 时，按 `../default-generation.md` 生成基础字段、默认值、引擎、字符集和主键。
- 新建表必须包含表对象创建语句、主键、必要索引、唯一约束、基础字段和注释。
- 新增字段必须说明默认值、空值语义、历史数据和老代码兼容影响。
- 新增唯一约束前必须说明存量重复数据检查或修复方案。
- 删除、缩短字段或修改字段类型必须说明调用方、历史数据、回滚和灰度窗口。
- 新增业务表默认生成 `TENANT_ID`、`ORG_CODE`；确认为无租户/组织隔离表时可豁免，并记录原因。
- 索引只能来自数据模型、唯一约束、明确查询/排序需求或外键关系，禁止凭空加索引。
- 可能锁表或长事务的 DDL 必须说明目标环境、执行窗口和降级方案。

## 交付要求

| 项 | 必填内容 |
| --- | --- |
| DDL 类型 | create/alter/index/drop |
| 默认规范 | 无参考时列出基础字段、默认值、引擎、字符集和索引来源 |
| 兼容影响 | 老代码、老客户端、历史数据、灰度发布 |
| 索引影响 | 命中查询、唯一性、存量冲突检查 |
| 执行风险 | 锁表、耗时、目标环境、执行窗口 |
| 回滚/补救 | rollback SQL、fixforward 或不可回滚说明 |
